# Локальный RAG по документации

Поиск по вашим документам «по смыслу» и «по словам» одновременно. Всё считается и хранится локально;
доступен из терминала (`rag`) и из Claude Code (MCP-сервер `docs-rag`).

```
документы (.docx .pdf .md .html .xlsx .pptx …)
   │  rag index / rag update
   ▼
парсинг с заголовками → чанки ~1500 символов → эмбеддинги bge-m3 (локально, MPS)
   │                                              │
   ▼                                              ▼
SQLite FTS5 (BM25 по основам слов)        векторы в том же SQLite
   └──────────── гибридный поиск (RRF) ───────────┘
                     │
        rag search  /  Claude Code: search_docs
```

## Запуск после скачивания

Нужны Python 3.11+ и ~6 ГБ свободного места. Работает на macOS, Windows и Linux.
Дальше считаем, что код лежит в `~/local-rag` (на Windows — `C:\Users\<вы>\local-rag`).

### Шаг 1–2: установка

**macOS / Linux** (Терминал):

```bash
cd ~/local-rag && python3 -m venv .venv && .venv/bin/pip install -e .
```

Сделать команду `rag` доступной, затем открыть новый Терминал:

```bash
mkdir -p ~/.local/bin && ln -sf ~/local-rag/.venv/bin/rag ~/.local/bin/rag && echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
```

**Windows** (PowerShell; при установке Python отметьте «Add python.exe to PATH»):

```powershell
cd ~\local-rag ; python -m venv .venv ; .venv\Scripts\pip install -e .
```

Сделать команду `rag` доступной, затем открыть новый PowerShell:

```powershell
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$HOME\local-rag\.venv\Scripts", "User")
```

Проверка на обеих системах — `rag --help`.

### Шаг 3–5: одинаково везде

3. **Проиндексировать документы** (при первом запуске скачается модель ~2,3 ГБ):
   ```bash
   rag index "/путь/к/документам" -c docs
   ```
4. **Проверить поиск:**
   ```bash
   rag search "ваш вопрос"
   ```
5. **Подключить к Claude Code** (по желанию; выполнить в папке проекта, затем открыть новую сессию Claude).
   macOS/Linux:
   ```bash
   claude mcp add docs-rag --scope local -- ~/local-rag/.venv/bin/rag-mcp
   ```
   Windows:
   ```powershell
   claude mcp add docs-rag --scope local -- "$HOME\local-rag\.venv\Scripts\rag-mcp.exe"
   ```

После изменения документов — `rag update`. Если `rag` не находится — откройте новое окно терминала.

### Сколько это занимает времени

Скорость индексации зависит от железа. Поиск после индексации быстрый везде: запрос считается за десятые доли секунды.

| Железо | Индексация | Пример: 7 600 фрагментов (~5,5 тыс. страниц) |
|---|---|---|
| Apple Silicon (MPS) | ~20 фрагм./с | ~7 минут |
| NVIDIA GPU (CUDA) | быстрее CPU в разы, не замерялось | — |
| Только CPU | ~5 фрагм./с и ниже | от 30 минут до полутора часов |

Индексация идёт один раз; дальше `rag update` пересчитывает только изменённые файлы.

### Отличия на Windows

- `.doc`, `.rtf`, `.odt` не читаются: они разбираются утилитой `textutil`, которая есть только в macOS.
  Такие файлы нужно пересохранить в `.docx`. Основные форматы (`.docx`, `.pdf`, `.md`, `.html`, `.xlsx`, `.pptx`)
  работают одинаково.
- Модель по умолчанию считается на CPU. Если есть видеокарта NVIDIA, поставьте сборку PyTorch с CUDA
  по инструкции с pytorch.org — код сам её подхватит.
- Кириллица в выводе включается автоматически; если консоль всё же ломает символы, используйте
  Windows Terminal или PowerShell 7.
- Проверено разработчиком только на macOS. На Windows код должен работать, но обкатан он меньше —
  о проблемах сообщайте в issues репозитория.

## Где что лежит

| Путь | Что это |
|---|---|
| `~/local-rag/rag/` | код (парсеры, чанкер, индекс, CLI, MCP-сервер) |
| `~/local-rag/data/index.db` | индекс — один файл; удалите его, чтобы начать с нуля |
| `~/local-rag/.venv/` | Python-окружение |
| `~/.cache/huggingface/hub/models--BAAI--bge-m3` | модель эмбеддингов (скачана один раз, дальше работает офлайн) |
| `~/.local/bin/rag` | ссылка на команду `rag` |

## 1. Добавить документацию

```bash
rag index "/путь/к/папке" -c имя_коллекции
```

- Коллекция — это метка, по которой потом можно фильтровать (`-c`). По умолчанию равна имени папки.
- Папка запоминается как источник, повторно её указывать не нужно.
- Скорость — примерно 20 чанков/с (≈ 50 страниц текста за 10–15 с) плюс ~10 с на загрузку модели.
- Форматы: `.docx .pdf .md .txt .html/.htm` (в т.ч. экспорт Confluence) `.xlsx .csv .pptx .doc .rtf .odt`.
  Картинки и сканы без текстового слоя не читаются (при индексации будет предупреждение ⚠ «нужен OCR»).

**Папка в «Документах» / «Рабочем столе» / iCloud.** macOS защищает эти папки, и Claude (desktop) их не видит.
Индексируйте из обычного Терминала — он запросит доступ один раз:

```bash
rag index "$HOME/Documents/Моя документация" -c docs
```

MCP-серверу доступ к исходникам не нужен: он читает только `data/index.db`.

## 2. Держать индекс свежим

```bash
rag update
```

Обходит все источники, переиндексирует только изменённые файлы (по дате/размеру/хэшу), удаляет из индекса
исчезнувшие. Если изменений нет — отрабатывает за доли секунды. Запускайте после выгрузки новой версии документации.

```bash
rag update --force              # пересчитать всё заново
rag remove "/путь/к/папке"      # убрать из индекса (файлы не трогает)
rag stats                       # что в индексе
rag sources -c pu               # список документов коллекции
```

## 3. Искать из терминала

```bash
rag search "что удалено из СБ в 2.0"
rag search "IDPPA-8891" -k 3
rag search "outbox retry ЛИМС" -p v2.0          # только файлы, в пути которых есть «v2.0»
rag search "синхронизация предприятий" -c pu --full   # чанки целиком
rag show 118 --around 2                          # найденный фрагмент + 2 соседних с каждой стороны
rag doc "черновик"                               # весь документ так, как его видит индекс
```

В выдаче у каждого результата: файл › раздел (стр.), `id` и два ранга — `вектор #N` (по смыслу) и `слова #N` (BM25).
Если хороший результат нашёлся только одним способом — это нормально, для того поиск и гибридный.

`--mode dense` / `--mode keyword` — посмотреть каждый способ отдельно (удобно, чтобы понять, почему что-то не нашлось).

## 4. Работать через Claude Code

После подключения (шаг 5 в «Запуске») в **новой** сессии проекта у Claude появятся инструменты:

| Инструмент | Что делает |
|---|---|
| `search_docs(query, k, collection, path_contains)` | гибридный поиск, возвращает фрагменты с источником и `chunk_id` |
| `get_context(chunk_id, before, after)` | дочитать раздел вокруг найденного фрагмента |
| `list_sources(collection)` | что есть в базе |

Просто спрашивайте, Claude сам решит, когда искать. Если хотите явно:

- «Найди в документации, как в 2.0 работает повторная отправка заявок в ЛИМС, и дай ссылки на разделы»
- «По документации: что зачёркнуто в разделе СБ? Сверь с v1.3»
- «Сделай тест-анализ синхронизации предприятий; требования ищи через search_docs, коллекция pu»

Первый поиск в сессии занимает ~10 с (загрузка модели), дальше — доли секунды.

Проверить подключение: в терминале `claude mcp list` или `/mcp` в интерактивном `claude`.
Подключить к другому проекту (выполнить в папке того проекта):

```bash
claude mcp add docs-rag --scope local -- ~/local-rag/.venv/bin/rag-mcp
```

Для всех проектов сразу — `--scope user` вместо `--scope local`. Отключить — `claude mcp remove docs-rag -s local`.

## Как формулировать запросы

- **Своими словами** работает: «где заводить сегменты для балансовой модели» найдёт «Операции» в ОМ.
- **Идентификаторы — точно как в документах**: `IDPPA-7340`, `SumNodeFlows`, имена ENV/эндпоинтов.
  Словесная часть поиска ловит их даже там, где «смысловая» промахивается.
- **Короче лучше**: 3–8 значимых слов. Длинный абзац размывает запрос.
- **Сузьте область**, если выдача смешивает версии: `-p v2.0`, `-c pu`.
- Не нашлось — переформулируйте синонимом (КК ↔ «контроль качества», ОПИ ↔ «объект производственной иерархии»):
  аббревиатуры и полные названия для словесного поиска — разные слова.

## Особенности разбора документов

- **Зачёркнутый текст** в .docx и удалённые правки (track changes), а также `<s>/<del>` в HTML
  сохраняются как `~~текст~~`. Их можно найти, но это пометка «удаляется», а не требование.
- **Заголовки** берутся из стилей Word (Заголовок 1…9, в т.ч. унаследованных), оглавления PDF, `#` в Markdown,
  `h1–h6` в HTML. Если в .docx стилей заголовков нет, короткие полностью жирные абзацы считаются заголовками.
- **Таблицы** режутся по строкам, шапка повторяется в каждом куске.
- Мелкие соседние подразделы склеиваются в один чанк с подзаголовками `### …` внутри.
- Комментарии рецензентов Word (выноски на полях) **не** индексируются.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `Нет доступа к …` | индексировать из Терминала (см. п. 1) или дать Claude доступ: Системные настройки → Конфиденциальность и безопасность → Файлы и папки |
| Нужный документ не находится | `rag sources` — есть ли он; `rag doc "имя"` — как он распарсился; попробовать `--mode keyword` |
| PDF с ⚠ «нужен OCR» | это скан; прогнать через OCR (например, `ocrmypdf`) и проиндексировать результат |
| В Claude нет инструментов `docs-rag` | открыть новую сессию; `claude mcp get docs-rag` должен показать ✔ Connected |
| Хочу другую модель эмбеддингов | удалить `data/index.db`, затем `RAG_MODEL=<модель> rag index …`; тот же `RAG_MODEL` задать MCP-серверу (`claude mcp add … -e RAG_MODEL=…`). Векторы разных моделей несовместимы |
| Отдельный индекс под другой проект | `RAG_DB=~/local-rag/data/other.db rag index …` (и тот же `RAG_DB` в env MCP-сервера) |
